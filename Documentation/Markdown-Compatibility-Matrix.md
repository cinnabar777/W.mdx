# Markdown compatibility matrix

This is the working, evidence-backed compatibility gate for opening, importing, rendering, and exporting Markdown dialects. “Verified” means the named fixtures and operations pass; it does **not** mean every feature in a dialect's entire ecosystem is supported. Unsupported or untested cases must stay visible here instead of being described as fully compatible.

The implementation targets Wmdx as its editable internal Markdown form. A conversion that cannot preserve meaning should report a warning and retain the original clipboard text rather than silently dropping content.

## Known exclusions and next gates

- CommonMark raw HTML interoperability remains separate from native Markdown parsing. All 77 upstream HTML cases are individually classified, with semantic-preservation or warning-checked intentional security-loss assertions and zero pending cases. This closes the pinned examples only, not every possible HTML nesting or import/export combination.
- All 575 parser-comparable CommonMark core cases pass rendered-semantic round trips through Wmdx, GFM, and Obsidian, including the 10 nested-emphasis cases previously known to fail. This does not close the separate raw-HTML track or the all-view interaction gate.
- Escape minimality now has per-backslash checks for 523 CommonMark core cases without authored escapes/bracket collisions, plus focused link, resource, media, table, footnote, and Wmdx-specific cases. Authored-escape and bracket/link-collision corpus cases, the remaining serializer branches, and all-view interactions still need reconciliation; do not mark Markdown flavor compatibility complete on this basis.
- GFM's nine-tag raw-HTML tagfilter is applied during HTML export. Raw HTML is still not fully rendered or converted identically in every editor view.
- The Obsidian fixture set is intentionally curated, not a claim of complete Obsidian compatibility. Note transclusion is now preserved as literal escaped text with an explicit warning when exported to CommonMark/GFM; it is not embedded there. Inline footnotes export as GFM reference footnotes with generated collision-safe labels; CommonMark retains inline source with a warning. GFM rendered/reader parity remains unverified. Plugin-defined syntax and other app-only features still need explicit support decisions and fixtures.
- The web export bridge now renders semantic HTML from the full Markdown source independently of editor mode, and browser tests verify it does not export CodeMirror markup. Android document-provider asset reads, separate CSS, and post-fix MHTML TOC-link behavior still need device acceptance.
- MHTML import now honors the MIME `start` root and `Content-Base`; broader real-world archive samples and CSS-dependent layouts still need fixtures.
- HTML/MHTML conversions preserve tested semantic content and related media bytes, but source-only distinctions can change: CommonMark has no native task list, CommonMark pipe tables are not standard, and arbitrary HTML does not carry Obsidian wikilink/callout identity unless the app adds metadata. Markdown link titles are retained; image tooltip titles and custom CSS have no general Wmdx field, so image title markup remains raw HTML with a warning.
- LaTeX, AsciiMath, Typst, and a WYSIWYG equation editor are not integrated. Obsidian inline/display math is kept literal in the tested conversion and HTML-export paths so Markdown emphasis cannot rewrite it, but equations are not typeset. This verifies syntax preservation, not math rendering or editing behavior.

Do not mark a row fully compatible just because import and export return text. The acceptance test must compare rendered meaning, verify the entire document including its tail, and record any warning or intentional loss.
